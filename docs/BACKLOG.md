# 后续迭代与验收

本清单区分待验证、运维改进和候选需求，不代表已经排期或获准改变在线行为。测试数量和性能结果记录在对应版本及当次输出中，不作为待办完成的替代证据。

## 待补真实验收

- [ ] **双账号同时使用**：第二个 QQ 账号方便测试时，在真实客户端同时对话，核对代号记忆、审批、模型偏好、文件回传和历史归属。每个账号只应看到自己的结果，现有自动化隔离测试不能替代该验收。
- [ ] **多模态完整链路**：在同一版本下覆盖图片、语音、视频、普通文件输入及文件、图片、音频回传，记录客户端、日期和失败表现。保留已有局部确认，不将其扩大为全覆盖。
- [ ] **手机端 Markdown 和按钮**：核对标题、列表、长代码分片、审批及询问按钮的实际排版和操作。QQ API 接受 Markdown 或返回消息 ID 不能证明手机显示正常或用户已读。
- [ ] **任务状态的实际 QQ 验收**：用新任务覆盖 `/status` 短编号、合并输入、执行中补充、审批及投递状态，在手机端核对摘要与本机时间线一致；自动化管线与离线演示不替代该验证。
- [ ] **Windows 重启与守护恢复**：受控重启并登录后检查计划任务、HTTP、QQ READY 和真实 Codex 任务；再观察服务退出及连续健康检查失败后的恢复。调查任务曾停止的原因，单次手动恢复不足以确认解决。

## 运维改进

- [ ] **安装检查与路径配置**：核对 Node、Codex、Python、FFmpeg/FFprobe 和 ASR 模型，降低换机时修正硬编码路径的成本。验收至少覆盖缺失依赖时的明确提示及新环境启动。
- [ ] **一致性备份与恢复演练**：覆盖 `runtime/`、需要保留的 `exports/` 和项目外账号工作目录，明确 SQLite WAL 的处理，实际恢复后检查历史、记忆、登录和文件归属。
- [ ] **独立开发实例方案**：设计独立端口、运行目录、Codex 数据、账号工作目录和机器人连接，避免与生产实例争用网关或状态。路径集中与隔离工作树尚不等于在线实例隔离。
- [ ] **故障状态诊断补齐**：任务时间线及账号诊断已实现，继续完善守护自身退出、长时间离线和模型路由故障的时间窗证据；不把一次重试成功当作根因修复。
- [ ] **日志与存储容量**：设计日志轮转、归档保留期限及容量提示；历史清理由用户选择，实施前保证可恢复。

## 候选改进

- [ ] **脱敏诊断导出**：仅包含必要状态和错误，排除凭据、原始对话、账号标识和本地私有路径。
- [ ] **代表性负载复测**：使用可复现数据评估多账号、长会话、短搜索词和长 Markdown，分别观察数据库、HTTP、浏览器绘制及内存。合成基准改善不直接等于 QQ 或远程桌面变快。
- [ ] 新增历史、模型和媒体需求时，先记录具体使用场景和验收条件，再纳入开发。

用户于 2026-10-16 在本机复核：会话切换正常，之前感知卡顿来自远程软件。保留已完成的加载锁和请求隔离，不把该反馈记为尚未确认的应用性能故障。
