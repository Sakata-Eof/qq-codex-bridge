# 演进路线

按已确认的顺序逐轮交付，每轮独立验证并保留回退点。以下是方向和验收目标；未勾选项目不代表已经实现。

## 1. 任务状态时间线与故障诊断

- [x] 为合并输入建立稳定任务标识，记录接收、合并、准备、执行、审批和结果投递阶段。
- [x] 分开显示模型执行结果与 QQ 投递结果，保留部分投递和不明确状态。
- [x] 实现 QQ `/status` 与本机历史页查看；查询按账号隔离，历史查看不改变执行会话。
- [x] 重启后把未完成状态标为待核实，不自动重跑任务或重发消息。
- [x] 覆盖去重、补充、停止、审批、失败、重启、过期响应和跨账号边界。

本轮以真实 SQLite 管线、HTTP 边界、浏览器回归及离线页面验证实现；真实 QQ 手机端新摘要的排版仍保留在 [待验收项](BACKLOG.md#待补真实验收)。

## 2. 独立开发模式与持续测试

- [ ] 明确区分生产配置、运行目录、账号工作区和网关连接，开发实例默认使用模拟通道。
- [ ] 建立可复现的 QQ/Codex 模拟场景及持续集成，自动执行离线检查和测试。
- [ ] 验收开发测试不读取生产凭据、不占用生产机器人、不修改生产历史。

## 3. 备份恢复与安装自检

- [ ] 安装自检提示缺失程序、模型、路径和登录状态，不把进程存在视为模型可调用。
- [ ] 建立配置、数据库、账号状态及项目外文件的备份方案和恢复预检。
- [ ] 在隔离目录实际演练恢复，验证历史、记忆、账号归属与工作文件。

## 4. 任务工作台与历史会话续聊

- [ ] 根据实际使用补充任务收藏、归档、产物查看和定位。
- [ ] 为“继续这个会话”设计明确操作，核对账号、项目和运行状态；历史浏览保持只读。

## 5. 项目预设与常用任务模板

- [ ] 每个账号独立保存允许的项目、模型、输出偏好和常用任务模板。
- [ ] 模板中的资料不提升权限，不共享其他账号的目录或会话。

## 6. 可安装、可迁移的发行版

- [ ] 有外部用户需求后完善配置向导、升级、回滚和新机器验收，再确定安装包范围。
- [ ] 依据实际第二入口需求评估渠道适配，保留统一任务、权限和历史边界。
