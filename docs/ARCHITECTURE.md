# 架构与设计约束

## 入口与依赖方向

根目录 `server.mjs` 保留原启动方式，实际组装在 `src/app.mjs`。组装层创建配置、QQ、账号、历史和发布通知实例，挂接事件并提供本机 HTTP 服务；独立模块通过参数与事件协作，不反向导入组装层。

| 模块 | 边界 |
| --- | --- |
| `src/core/` | 账号与任务生命周期、Codex JSON-RPC、模型、记忆、连续输入 |
| `src/qq/` | QQ 鉴权和网关、事件规范化、消息投递、控件、指令和 Markdown |
| `src/history/store.mjs` | SQLite 写入、会话、查询、导入、展示合并和导出 |
| `src/media/processor.mjs` | 来源校验后的附件下载、转码、识别、生成文件保存与回传 |
| `src/http/` | 浏览器认证和历史路由；历史路由使用注入的配置及服务 |
| `src/ops/` | 一次性发布通知与本机投递记录 |
| `src/shared/path-security.mjs` | 共用目录边界判断，不依赖任务或 QQ 网关 |
| `public/` | 管理页、历史页及浏览器请求恢复 |

事件解析和媒体 URL 校验分别位于 `src/qq/events.mjs`、`src/qq/media-url.mjs`。账号与媒体模块共用目录校验，避免为了复用工具而导入整个网关或任务实例。

`src/paths.mjs` 从模块位置解析项目根目录，统一 `runtime/`、`exports/`、`public/`、维护脚本和默认工作目录。模块移动不会将运行数据挪到 `src/`。根目录的启停、守护及通知兼容入口保留；实际媒体与运维脚本位于 `scripts/`。路径集中不代表已经支持任意运行目录或第二个独立在线实例。

## 消息与任务链路

QQ 官方网关 → `qq/client.mjs`、`qq/events.mjs` 规范化事件 → `core/accounts.mjs` 校验配对账号和去重 → 对应账号的 `Bridge` → 独立 Codex App Server 进程 → 当前 QQ 会话中的结果、审批与媒体。

`core/codex.mjs` 只负责 JSON-RPC 传输；`core/bridge.mjs` 管理 thread/turn、审批、任务与投递。模型执行结束和 QQ 投递结束是不同阶段，投递尚未完成时保持忙碌，防止新任务或模型切换打乱状态。

`core/message-batches.mjs` 按账号和私聊/群聊合并普通输入，安静 3 秒或累计 10 秒提交；状态、审批和停止等控制命令绕过等待。合并输入保留每条源消息，确定实际 thread 后逐条关联历史。

`Bridge` 按会话串行准备和提交输入。活动轮通过带 `expectedTurnId` 的 `turn/steer` 接收补充；该轮结束后排入下一轮。只有明确拒绝且已确认原轮结束时才允许改为新轮，响应不明确时不重放。附件准备失败不能让缺少附件的说明先行执行。

停止会取消对应会话未提交的输入；旧操作随后失败不会误取消新输入。结果发送使用原任务完成时的文字、附件及源消息快照，后来的 `/status`、追问或会话重置不能改变已完成结果的归属。

## 账号隔离与记忆

账号目录键由机器人 AppID 和 QQ 用户标识哈希派生。`runtime/users/<key>/` 保存该账号的会话状态、私有记忆、去重记录与 `codex-home/`。进程、工作目录、会话、审批、模型偏好和历史均按账号独立，任务工作目录由账号配置限定，禁止重叠与越界。

账号首次创建时初始化专属 Codex 配置，登录资料仅在本机使用。已有会话迁移只匹配该账号记录的 thread。管理页显式维护全局记忆，QQ `/remember` 只写入本账号私有记忆；轮换会话只携带本账号的近期摘要及允许的记忆。

模型列表与推理强度来自本机 Codex，显式选择保存在对应账号配置，下一次 `turn/start` 使用，保留当前 thread。执行、准备和结果投递期间拒绝切换。图片输入遇到不支持图片的模型时提示更换，不静默丢弃。

模型原生上下文压缩、桥接会话轮换和长期记忆是不同机制。默认完成 40 轮或空闲 6 小时后，在下次任务开始时轮换；实际阈值以本机保存的配置为准，不中断活动任务。

## 历史存储与展示

Codex 原始会话记录模型和工具执行过程。`runtime/history.sqlite` 记录 QQ 收发、模型结果、附件、审批提示及错误，两者通过 thread ID 关联。Codex 生成了结果不能证明 QQ 已成功投递，因此保留独立审计。

数据库采用 WAL、账号/会话/时间索引、游标分页和 FTS5 trigram 搜索。旧 Codex 日志只从账号专属目录按变更导入，不在页面查询时扫描。导入记录标为 `codex-import`，不能视为 QQ 成功发送。`historyResetBefore` 阻止已清理的旧记录再次补入，不影响 Codex 原始会话、工作文件和记忆。

同账号、thread、源消息、时间边界及正文匹配的完整结果和成功投递可以合并展示，数据库与导出保留原始事件。分段或截断投递仍保留完整结果并折叠；失败或未确认投递保持可见。跨页匹配不扩大到其他账号或会话，列表区分原始记录数与本页合并数。

消息默认每页 30 条，可选 20、50、100 条；会话列表也分页。三字符及以上搜索通过 FTS5 trigram 后核对精确子串，一至二字符在当前账号与会话内扫描。导出按 500 条一批写入文件，避免一次构造全部历史。原始审计、正文复制及导出均保留完整文本。

历史 HTTP 路由在 `src/http/history-routes.mjs`，通过依赖注入访问账号、历史和 QQ 状态。组装层先完成 Host、Origin 和登录检查，再分派历史请求；路由提取不改变账号范围和附件目录校验。

## 浏览器加载与登录

HTTP 仅绑定本机地址。管理 API 使用 Bearer 或签名 HttpOnly Cookie，Cookie 使用 SameSite=Strict；服务同时检查 Host 与 Origin。浏览器首次用本机验证入口建立登录，会话正常重启后仍有效，新浏览器需要单独验证。

普通读取有超时与重试入口，管理页和历史页通过各自轮询恢复；写入请求不自动重放。未登录、暂时连接失败和真实空记录分别显示，已有页面数据不会因一次连接失败被误当成空历史。

切换账号或会话时立即清空旧消息并显示加载动画，分页和刷新期间标示加载状态。加载期间账号、会话列表和相关控制禁用鼠标与键盘操作；取消遗留请求、校验请求代次并丢弃延迟事件，避免旧结果覆盖新选择。消息绘制后解锁；失败后恢复操作和读取重试。

附件首次点击才请求，当前页面可复用已加载缓存，切换页面释放。每 10 秒检查连接、会话摘要及新消息数量，新消息通过提示让用户读取最新一页，不无限累积 DOM。数据库、请求、绘制、附件下载及远程桌面的响应分别测量，不能用其中一个时间推断其余环节。

## QQ 控件与文本

QQ 指令按钮使用消息型动作（`action.type=2`），复用账号授权与消息去重。审批和询问凭证绑定账号、thread、turn 与请求，防止串号、过期和重复执行。客户端按钮可见性不替代本机授权；文字审批和回答保留为备用入口。

面板通过 `/v2/panels` 同步，只维护本服务标记的条目并保留其他自定义内容。底部菜单通过 `/v2/menu` 同步，提供 Codex、会话记忆两个分组；同名冲突或超出本地设定的容量时拒绝覆盖。同步后回读核对，报告写入 `exports/verification/reports/verification-commands.json`。

普通回复和发布通知默认使用 QQ 原生 Markdown，`replyFormat: "plain"` 可改为纯文本。分片优先在段落或整行边界，避免拆断 Unicode 字符和代码围栏。本地文件链接显示为可读文本，实际文件走附件上传。

只有平台明确拒绝 Markdown 格式时，才将该片及后续片降级为纯文本；超时和状态不明确时不重发，已成功片段不重放。历史保留原始正文、实际格式及发送内容。客户端支持的具体排版和按钮行为仍以真实验收为准。

## 多模态与投递

图片转换为模型图片输入；语音优先使用 QQ 自带转写，缺失时调用本地 faster-whisper；视频抽样画面并转写音轨；普通文件保存到发送账号工作目录后提供给模型。当前代码限制每批 8 个附件、单文件 50 MB、视频 10 分钟，音轨失败会明确标注不能据此判断说话内容。

下载及每次重定向都经过媒体来源校验，只允许可信 QQ/Tencent 来源，拒绝本地地址和伪装域名。生成文件和回传文件经过账号目录校验。最终回复中的允许路径可以触发附件回传，单次最多三个；部分音频先转换为 MP3。

媒体处理在 `src/media/processor.mjs`，转写和语音脚本在 `scripts/media/`。文件格式、平台回复次数和消息有效期可能限制投递；失败保留本地结果供重新取回，不通过自动重发掩盖不明确结果。

## 发布通知

`src/ops/release-notifications.mjs` 独立管理发布通知，不创建模型任务或共享账号会话。发送前持久化尝试，结果和平台消息 ID 留在本机；同一发布 ID 和账号只尝试一次。仅通知当前已绑定私聊账号，正文使用通用说明，不包含任何账号对话或文件。

管理界面和消息历史界面改动不发送 QQ 通知。其他改动还需本机 `releaseNotificationsEnabled=true`、完成验证并上线，操作流程见 [RUNBOOK](RUNBOOK.md#发布通知)。根 `notify-release.mjs` 是兼容入口，实际脚本位于 `scripts/ops/`。
