# 性能基准

运行 `npm run benchmark` 可重现以下比较。脚本在系统临时目录创建合成 SQLite 数据库，结束后关闭并清理；不会读取在线账号数据，也不会连接 QQ 或模型。时间为同一进程预热后的中位数，单位为毫秒，具体数值随机器和负载变化。

## 历史结果关联

2026-10-16 在本机 Windows / Node.js 24 环境生成两个账号、合计 10,000 条记录，每页 100 条。原查询计划按会话和时间扫描，再过滤消息 ID；为两条结果关联查询明确选择已有的 `messages_event(user,message_id,kind)` 索引后，先定位单条消息的关联记录。

| 完整页面查询 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 中位耗时 | 50.257 | 0.767 |
| P95 耗时 | 64.051 | 0.913 |

没有新增索引或修改数据库结构。账号、会话、消息 ID、时间及正文的匹配条件完整保留。基准比较两个账号、四种页大小和连续分页，共 64 页的完整输出，结果一致。原有测试继续覆盖相同结果合并、失败或部分投递、附件、跨页及跨账号隔离。

## Markdown 分片

分片扫描改为累计 UTF-16 长度及末尾字符，在选定片段后统一生成正文，减少长代码块扫描中的重复字符串拼接。分片边界、原始正文、路径处理及围栏补全规则保持一致。

| 合成输入 | UTF-16 长度 | 优化前中位耗时 | 优化后中位耗时 |
| --- | ---: | ---: | ---: |
| 普通段落与列表 | 46,500 | 5.059 | 4.109 |
| 代码围栏 | 132,017 | 58.024 | 13.056 |
| 本地路径与网页链接 | 91,200 | 8.609 | 8.974 |

代码块场景收益明显；链接场景本次测量略有波动，没有普遍加速的结论。固定随机种子的 500 组差分检查比较分片结果与错误行为，均与原算法一致，另有随机输入的正文还原、长度上限及 Unicode 边界检查。

## 使用范围

以上是合成规模与指定文本的比较。当前本机历史库较小，此前实际读取已为毫秒级；用户已确认远程操作时的卡顿来自远程软件。本轮基准用于评估数据增长和长回复场景，页面体验仍以实际本机或客户端检查为准。
