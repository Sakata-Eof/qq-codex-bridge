# QQ–Codex Bridge

[GitHub 仓库](https://github.com/Sakata-Eof/qq-codex-bridge) · [MIT 许可](LICENSE)

本服务通过 QQ 官方机器人接口调用本机 Codex app-server。账号必须通过本机生成的一次性配对码绑定。

## 从源码开始

本项目主要面向 Windows 本地运行。准备 Node.js 24、已安装并登录的 Codex，以及自己在 QQ 开放平台创建的机器人；进入项目目录执行 `npm ci`，再运行 `./Start.ps1`，在自动打开的本机页面填写机器人凭据并配对账号。需要媒体功能时还须准备 FFmpeg、Python 和 ASR 模型，具体路径在本机配置中核对。

自动登录启动和开始菜单入口分别由 `Install-Autostart.ps1`、`Install-Launchers.ps1` 安装。当前守护脚本仍有固定 Node 路径等本机安装假设，换机前请读 [维护手册](docs/RUNBOOK.md)，不能直接把已有作者环境当作通用安装器。运行 `npm test` 验证离线逻辑。

## 打开和启动

已安装 Windows 开始菜单入口：按 Win 搜索“Codex QQ 控制台”或“Codex QQ 消息历史”即可打开，自动启动服务并验证当前浏览器，无需查找脚本。验证后同一浏览器可直接收藏并打开 `http://127.0.0.1:17329/` 或 `/history`。重新安装入口可运行 `Install-Launchers.ps1`。

运行 `Start.ps1` 打开含本机访问凭证的配置页。配置页可进入“消息历史”，选择账号和会话、搜索消息、点击预览附件并导出当前会话 JSON。访问凭证只在本机页面使用，请勿分享 `runtime/config.json` 或 `runtime/setup-url.txt`。

验证链接首次打开后建立仅本机服务使用的浏览器登录会话（HttpOnly、SameSite=Strict，30 天），同一浏览器的新标签页和历史页可直接打开普通地址。旧标签页保存的凭证也会自动迁移；服务正常重启不使登录失效。新浏览器、清除 Cookie、凭证改变或会话到期后，运行 `Start.ps1` 重新验证。未登录、网络失败和真正无记录会分别显示；普通读取 10 秒超时并自动重试，配置页刷新不会叠加未完成请求。已经加载的数据在临时连接失败时保留，消息页第一次读取失败后也会重试。更改设置的请求不会自动重发，以免重复操作。

已安装 Windows 登录启动任务 `QQ-Codex-Bridge`，运行 `Watchdog.ps1`：进程退出自动重启，HTTP 连续异常会重启服务；QQ 连接独立执行心跳和断线重连。重启 Windows 后需要登录当前用户。电脑睡眠或关机时无法处理消息。

`Stop.ps1` 用于主动停机；重新启动前运行 `Install-Autostart.ps1`，它会清除停机标志并启动守护进程。

## 账号、记忆与上下文

普通消息会在停顿约 3 秒后自动合并，连续发送最长等待 10 秒。只发一张图片也会自动处理；先发要求再发图片、先发文件再补说明均可。任务开始后的新内容会追加到当前任务，任务已结束时作为同会话下一轮处理。`/status`、审批与 `/stop` 即时响应；`/stop` 同时取消尚未提交的消息。每批合计最多 8 个附件。

各账号拥有独立 Codex 进程、CODEX_HOME、工作目录、会话、审批和私有记忆。群聊默认不开放。账号项目目录不可重叠。

全局记忆在本机配置页编辑，供全部已绑定账号使用。QQ `/remember 内容` 只写入当前账号的私有记忆；`/memory` 查看，`/forget 编号` 删除。私有记忆不会自动并入全局记忆。

Codex 使用模型原生上下文压缩；桥接层默认在完成 40 轮或空闲 6 小时后，于下次任务开始时换会话，携带本账号近期摘要及记忆。活动任务不会因此中断。配置页可调整轮数与空闲时间，`/context` 查看当前情况，`/new` 手动开始新会话。

## 多模态

每个账号可通过 QQ 模型按钮或本机配置页独立选择模型与推理强度。列表由本机 Codex `model/list` 获取，推理强度按返回的支持范围验证；实际模型访问以任务成功执行为准。当前账号首次配置继承其专属 `codex-home/config.toml`，已核实 `gpt-6.1-sol`／`high`。显式选择保存到 `runtime/config.json` 的对应用户条目，重启后保留；不修改其他 QQ 账号或桌面 Codex 默认。切换保留当前 thread，下次 `turn/start` 传入模型和推理强度。任务启动、执行和结果发送期间拒绝切换。文本模型遇到图片输入时提示换模型，不静默丢弃图片。

图片转换为模型图片输入；语音优先使用 QQ 提供的转写，其次由本地 faster-whisper 识别；视频输入抽样画面与音轨转写；普通附件保存到发送账号目录后提供给模型。单个文件上限 50 MB，视频分析上限 10 分钟。

模型最终回复中的绝对路径 Markdown 文件链接会自动发送到当前 QQ 会话，单次最多三个附件；原生图片生成结果也会复制到当前账号项目并发送。支持 QQ 图片、MP4 视频、MP3/WAV/OGG/SILK 音频及普通文件；FLAC/M4A/AAC/AIFF/AMR 先转换为 MP3。文件发送采用官方分片上传接口；QQ 接受消息后记入历史，失败保留本地结果并提示 `/file` 重取。QQ 私聊每条用户消息最多四次回复，群聊最多五次，因此多附件任务会受该限制。

图片 URL 兼容 QQ NT 域名 `nt.qq.com.cn` 与语音域名 `qqbot.ugcimg.cn`，可信腾讯 HTTP 链接升级为 HTTPS；本地地址和伪装域名仍拒绝。程序使用绝对路径，避免 Windows 登录启动环境找不到 Codex、FFmpeg 或 Python。

## QQ 官方控件（2026-09-30 核实）

[官方 Markdown 文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)说明，自 2026-04-23 起所有机器人可在单聊、群聊使用自定义 Markdown，无需单独申请模板；频道仍需内邀开通。

[单聊消息接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)支持 `keyboard.content.rows` 自定义按钮。当前桥接已使用指令按钮：审批提供“同意本次”和“拒绝”，询问提供选项按钮，同意、停止、新会话有二次确认。审批与回答按钮携带随机凭证，并校验账号、会话、活动轮次和未处理请求，过期或重复点击不会执行。文字 `/approve`、`/deny`、`/answer` 继续可用；客户端不支持或 QQ 明确拒绝按钮格式/权限时回退文字，网络超时不会盲目重复发送。

固定指令面板通过[官方 `/v2/panels` API](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_panels.post.html)同步，无需逐项手填。连接 QQ 后自动核对，配置页“同步 QQ 指令列表”可手动重试。专用单聊全局面板显示 12 个常用指令，与 `/help` 一致；文件、语音测试、删除记忆和手动审批等内部备用指令保持可用，但不显示在公开列表中。参数需用户补全。仅维护带 `qq-codex-bridge:commands:v1` 备注的面板，保留其他面板和本面板新增的自定义条目，超过单面板 20 项限制则拒绝覆盖。

同时通过[官方 `/v2/menu` API](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_menu.put.html)配置聊天底部两个快捷菜单：Codex、会话记忆。旧“文件音频”分组已移除，正常上传附件用 QQ 自带发送功能，回传附件可直接用自然语言要求。保留已有自定义菜单，同名冲突或超过 10 项上限则拒绝覆盖。手机 QQ 可重新进入机器人聊天刷新，再查看底部菜单或输入 `/` 唤起指令面板。写入后均从 QQ 回读核对，记录在 `verification-commands.json`；鉴权失败会在本机状态和日志中显示实际错误。

当前使用 `action.type=2` 指令按钮，单聊点击后发送普通 QQ 消息，复用现有鉴权和去重；群聊只填入指令供用户确认。客户端按钮权限使用 `permission.type=2`，因为 C2C 的 `user_openid` 用于指定用户键盘权限时，手机 QQ 实测提示“无权限操作”；授权与隔离由本机校验账号、会话和审批凭证完成。`action.type=1` 回调按钮需要另外订阅互动事件，本桥接不使用该类型。

## 历史看板与存储

Codex 的账号专属 `codex-home/sessions` 保存模型会话和执行记录。服务数据库保存 QQ 实际收到、成功发送的消息、附件路径、审批按钮及错误，并用 Codex thread ID 关联会话；它不复制完整的 Codex 工具日志。旧版本曾从账号专属 Codex 日志补录用户和最终回复，因此该部分标有 `codex-import`，不代表 QQ 实际投递成功。补录仅在启动和账号初始化时检查变更文件，不在看板查询时扫描日志。

同一账号、会话和任务消息的完整结果与成功发送记录内容完全相同时，看板只展示对应“发送 · 任务结果”，数据库和 JSON 导出仍保留原始事件。比较通过消息索引查找，跨页也能匹配，其他账号或会话的相同文本不会合并。分段、截断回复的完整结果改为点击展开；未找到一致发送记录时保留结果并提示投递未确认。列表计数注明原始记录数及本页合并数量。

有正文的消息右上角提供“复制”，复制完整原文并保留换行；折叠的任务结果也可直接复制全文。复制成功或失败会显示提示。

SQLite 使用 WAL 和账号／会话／时间索引。消息默认每页 30 条，可选 20、50、100 条；采用游标分页，翻页不会无限累积 DOM。会话列表也按页查询。标题取首次任务内容，可手动修改并持久保存。首次打开不请求附件，点击后才下载预览，当前页面收起再打开复用缓存；切换页面释放缓存。每 10 秒仅检查连接、会话摘要和新消息数量，收到新消息显示提示，点击后读取最新一页。

搜索限定当前账号和会话，三字符及以上使用 FTS5 trigram 索引再核对精确子串；一至二字符在该会话范围内扫描。导出按 500 条一批写入文件，避免一次构造全部历史。`verification-history-performance.json` 记录 10 万条模拟数据的数据库测试，查询时间不包含网络、附件下载或浏览器渲染。

按用户要求清理的旧记录备份在 `runtime/history-backups`。配置的 `historyResetBefore` 阻止清理前的 JSONL 和 Codex 日志再次补入；Codex 原始会话、工作文件和记忆不受影响。
